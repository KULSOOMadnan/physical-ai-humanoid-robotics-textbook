# Data Model: Physical AI & Humanoid Robotics Textbook

**Date**: 2025-12-04
**Feature**: 001-humanoid-robotics-textbook
**Plan**: specs/001-humanoid-robotics-textbook/plan.md

## Key Entities and Relationships

### 1. Textbook

*   **Description**: The overarching educational product, a comprehensive guide to Physical AI and Humanoid Robotics.
*   **Fields**:
    *   `title`: "Physical AI & Humanoid Robotics Textbook" (String)
    *   `version`: Current version of the textbook content (e.g., 1.0.0) (String)
    *   `publication_date`: Date of the textbook's release (Date)
    *   `authors`: List of authors/contributors (List of Strings)
    *   `chapters`: Ordered list of `Chapter` entities (One-to-Many relationship)
    *   `glossary`: Collection of `Term` definitions (One-to-Many relationship)
    *   `appendices`: Supplementary materials (List of Strings, referencing `Content Module`s)
*   **Relationships**: Contains `Chapter`s, `Glossary` terms, and `Content Module`s (for appendices).

### 2. Chapter

*   **Description**: A self-contained unit of learning within the textbook, focusing on a specific topic.
*   **Fields**:
    *   `chapter_number`: Unique identifier for the chapter (Integer)
    *   `title`: Title of the chapter (String)
    *   `learning_objectives`: Key outcomes students should achieve (List of Strings)
    *   `content_modules`: Ordered list of `Content Module` entities within the chapter (One-to-Many relationship)
    *   `quizzes`: References to end-of-chapter quizzes (List of Strings)
    *   `projects`: References to end-of-chapter projects (List of Strings)
*   **Relationships**: Belongs to a `Textbook`. Contains `Content Module`s.

### 3. Content Module

*   **Description**: A logical grouping of related learning material, the atomic unit of content.
*   **Fields**:
    *   `module_type`: Type of content (e.g., "Text", "Code Example", "Diagram/Figure", "Exercise/Lab", "Case Study", "Video Demonstration") (Enum)
    *   `title`: Title or brief description of the module (String, optional)
    *   `content`: The actual text, code, image path, or link for the module (String/URL)
    *   `order`: Display order within its parent `Chapter` (Integer)
    *   `references`: Citations or links to external sources (List of Strings/URLs)
*   **Relationships**: Belongs to a `Chapter` or `Textbook` (as an appendix).

### 4. Student

*   **Description**: The target reader of the textbook.
*   **Fields**:
    *   `background_ai`: Boolean, assumed basic AI knowledge.
    *   `background_programming`: Boolean, assumed Python proficiency.
    *   `background_linear_algebra`: Boolean, assumed basic linear algebra.
*   **Relationships**: Interacts with the `Textbook` content. (Not a stored entity in the textbook itself, but a conceptual target).

### 5. Humanoid Robot

*   **Description**: The physical system that is the subject of control and interaction.
*   **Fields**: (Conceptual entity within textbook content, not a data object)
    *   `components`: Actuators, sensors, chassis, power systems (conceptual)
    *   `degrees_of_freedom`: Number of movable joints (conceptual)
*   **Relationships**: Controlled by `Control Algorithm`s. Interacts with `Simulation Environment` and real world. Generates `Sensor Data`.

### 6. Simulation Environment

*   **Description**: Virtual platforms for testing and developing robot behaviors.
*   **Fields**: (Conceptual entity within textbook content, not a data object)
    *   `name`: e.g., "Isaac Sim", "Gazebo" (String)
    *   `features`: Physics engine, rendering, robot models (conceptual)
*   **Relationships**: Hosts `Humanoid Robot`s. Provides `Sensor Data`. Executes `Control Algorithm`s.

### 7. Sensor Data

*   **Description**: Inputs from the robot's environment (e.g., vision, touch, proprioception).
*   **Fields**: (Conceptual entity within textbook content, data structures would be language-specific in code examples)
    *   `type`: e.g., "camera", "IMU", "joint_encoder", "force_torque" (Enum)
    *   `format`: e.g., "image", "vector", "scalar" (String)
    *   `timestamp`: Time of data capture (Timestamp)
    *   `value`: Raw or processed sensor reading (Any)
*   **Relationships**: Generated by `Humanoid Robot`s. Processed by `Control Algorithm`s for perception.

### 8. Control Algorithm

*   **Description**: Software logic to direct robot actions.
*   **Fields**: (Conceptual entity within textbook content, actual code in `Code Example` modules)
    *   `name`: e.g., "PID controller", "Inverse Kinematics", "Reinforcement Learning Policy" (String)
    *   `input_data`: Types of `Sensor Data` or desired states (List of Types)
    *   `output_actions`: Types of commands to robot actuators (List of Types)
    *   `description`: Explanation of algorithm's function (String)
*   **Relationships**: Consumes `Sensor Data`. Generates commands for `Humanoid Robot`.

### 9. Motion Plan

*   **Description**: A sequence of movements for the robot to achieve a goal.
*   **Fields**: (Conceptual entity within textbook content, data structures would be language-specific)
    *   `goal`: Target state or task (String)
    *   `trajectory`: Sequence of waypoints or joint commands (List of Poses/JointStates)
    *   `duration`: Expected time to execute (Float)
    *   `safety_constraints`: Obstacle avoidance, joint limits (List of Constraints)
*   **Relationships**: Generated by planning modules within `Control Algorithm`s. Executed by `Humanoid Robot`.

## Relationships Summary

*   `Textbook` contains `Chapter`s.
*   `Chapter`s contain `Content Module`s.
*   `Content Module`s can be `Code Example`s, `Diagram/Figure`s, `Exercise/Lab`s, `Case Study`s, etc.
*   `Humanoid Robot` generates `Sensor Data` and executes `Control Algorithm`s and `Motion Plan`s.
*   `Simulation Environment` hosts `Humanoid Robot`s and provides `Sensor Data`.
*   `Control Algorithm`s process `Sensor Data` to generate actions or `Motion Plan`s.
